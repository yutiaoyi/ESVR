90 帧的干净单变量对照(高亮行)现在有了结论:与"90 帧独立原生 ESVR"完全相同的配方(train_chunk.py 原生调优、自适应增密、分参数组学习率),唯一变量是 CUDA 修复 + position 学习率按 ÷4096 反向补偿, 90 帧全部独立训练、互不共享参数。结果 41.22dB → 39.38dB,真实降幅 −1.84dB,和下面单帧诊断量出来的 −1.83dB 几乎完全一致——两次独立测量互相印证,不是偶然。90 帧结果全部落在 38.65~39.94dB 的窄区间内, 没有失败帧,说明这个降幅是稳定、系统性的,不是某几帧异常拖累平均值。

这一行能跑通,建立在下面这次单帧诊断的基础上——直接把原生配方套到修复后的 CUDA 上会训练发散、显存溢出, 原始 position_lr(8e-6→1e-6)是在"位置梯度被压缩了 4096 倍"这个 bug 存在的前提下调出来的, 梯度修正后同样的学习率相当于步长突然放大了 4096 倍。单帧诊断把 position_lr 按 ÷4096 反向补偿 (保持"学习率×梯度"这个有效更新幅度不变),其余全部原样保留,训练才重新稳定收敛。 详见 output/experiments/vorts90_cuda_fixed_lr_only/RESULTS.md 和 output/experiments/vorts0001_cuda_fixed_lr_only/RESULTS.md(后者还记录了一次学习率补偿方向搞错、 导致图元数骤减到 5,409 的失败尝试,作为负面结果保留未删除)。

前三行(单帧基线、90帧独立原生、90帧独立简化)都是"每帧独立训练、互不共享参数"的结果,用来衡量共享/动态表征 牺牲了多少保真度换取压缩率——不是三种时变方法的直接竞争对手。其中第三行(38.86dB,train_dynamic.py --allow-single-frame)和第一行不能直接对比 CUDA 修复的影响,因为同时换了训练脚本、图元策略、迭代次数、 学习率四个变量——这也是为什么需要专门补跑高亮行这个真正的单变量对照。

过程中定位并修复了两个真实架构级 bug(透明度激活函数死区导致训练永久崩溃;最终尺度无下限导致协方差数值退化产生 NaN), 均已通过多组随机种子压力测试验证。三个方法中唯一在增密开启的情况下完成完整原生训练步数的。
评测协议:全部实验均使用全 90 帧参与训练(非留出测试划分),PSNR 为归一化 [0,1] 值域下的 3D 体素 PSNR, 逐帧计算后取算术平均。每个已标记"当前最终/当前代表"的实验均已完成 checkpoint 重载一致性校验(逐字节零误差)。 完整配置、验证记录与详细讨论见各自目录下的 RESULTS.md。

规模 / 耗时列:训练时长直接取自各次运行自己的训练日志(train.jsonl/monitor.jsonl 的 seconds 字段,或 RESULTS.md 已记录的墙钟时间),同一次训练机器(RTX 5090)。 参数量与模型大小从每次运行的 checkpoint.pt 里直接加总权重张量元素数重新计算(float32,4 字节/参数), 不包含 Adam 优化器的动量缓冲区(实际磁盘上 checkpoint.pt 文件因此会更大,仅用于断点续训, 不代表模型本身的大小)。

可视化列:点击"曲线"/"切片"/"GIF"直接在新标签页打开对应实验自己生成的 quality_curves.png(逐帧 PSNR/MAE 曲线)、slice_comparison.png(GT/预测三视图切片对比)、 training_frames_dvr.gif(90 帧体渲染逐帧对比动图,GT｜预测｜体素级绝对误差｜渲染图像级绝对误差四联并排。 第三联是"先算体素误差再体渲染",第四联是"GT/预测各自体渲染成图后再对两张图直接做像素差"——体渲染是有损非线性合成, 两者不必然一致,第四联反映的是"看起来差多少",第三联反映的是"数据本身差多少"。两个误差面板都用 inferno 配色、 上限固定在归一化 0.1)原始文件。标注"未生成"的实验没有运行过可视化脚本 (多为单帧静态实验,或诊断性中间版本),不代表训练本身有问题。
