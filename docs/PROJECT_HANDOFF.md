## 0. 一段话摘要

本项目把 ESVR(一种基于椭球图元的稀疏体渲染静态重建方法)扩展到支持时变(4D)数据,做法是把三种不同的动态高斯表征方法(Deformable 3DGS、4DGS、4D-Scaffold-GS)分别接入 ESVR 的 3D 标量体素监督框架,作为三条并行、可比较的分支。三种方法均已实现并在真实 90 帧涡旋模拟数据上验证,当前最好结果是 Deformable-MLP 的 **28.90dB**(`codex/deformable-esvr` 分支)。过程中发现并修复了一个影响全部三个分支的共享 CUDA 梯度 bug,并已用严格的单变量对照(90 帧规模)量化出这个修复本身的真实代价(−1.84dB)。**当前最需要关注的两件事**:(1)全部实验都是 90/90 帧训练,从未做过留出时间点的泛化测试,不确定三种方法是否真的学到了可泛化的运动场;(2)所有代码目前只存在于本地磁盘,没有推送到任何远程仓库——这是已知状态,用户已明确决定暂不推送(本项目本来就是纯本地开发),但下方记录的分支重名冲突风险需要在真正决定推送时处理。

## 1. 项目目的

**背景**:ESVR(*3D Ellipsoid-based Sparse Volume Rendering via Structure-aware Primitive Learning and Per-primitive Ray Sampling*,论文见 arXiv:2608.05564,原始代码库 `hvcl/ESVR`)是一种用可微分椭球图元直接拟合、渲染大型稀疏 3D 标量体数据(如医学影像、科学模拟数据)的方法,本质是"3D Gaussian Splatting"思路在标量体渲染上的迁移,监督信号是体素级别的标量值(L1/SSIM),不涉及相机、RGB、视角相关效果。

**扩展目标**:原始 ESVR 只处理单个静态体数据。本项目要让它具备处理**随时间变化的体数据序列**(4D:3D空间 + 时间)的能力。做法不是自己发明一种新的时变表征,而是把学术界已有的三种成熟的"3D→4D"动态高斯表征方法,分别按照它们各自的思路接入 ESVR 的监督框架,替换掉它们各自原本依赖的相机/RGB/视角相关监督:

1. **Deformable 3D Gaussians**(`ingra14m/Deformable-3D-Gaussians`)——canonical(标准姿态)椭球 + 一个独立的形变 MLP,输入位置+时间,输出该时刻相对 canonical 姿态的位移/旋转/尺度偏移。
2. **4D Gaussian Splatting**(`fudan-zvg/4d-gaussian-splatting`)——椭球本身就是 4D 的(3 个空间维度 + 1 个时间维度),运动通过对 4D 协方差做时间条件化(Schur 补)自然产生,没有额外的网络。
3. **4D-Scaffold-GS**(`raikuma/4D-Scaffold-GS`)——稀疏"锚点" + 共享 MLP,从锚点特征解码出若干子椭球,用恒定速度模型描述运动。

选这三种是因为它们代表了三种本质不同的运动建模思路(网络驱动的形变 / 原生4D协方差 / 锚点+隐式解码),把它们放在同一个 ESVR 体素化渲染器和同一批真实数据(90 帧涡旋流场模拟)下,可以在尽量控制变量的前提下比较三种运动建模思路各自的优劣,以及它们和 ESVR 这个特定的、非常规的(加法而非透明度合成)渲染器之间的兼容性。

## 3. 核心技术背景

理解后面所有实验结果之前,必须先理解这几个贯穿全项目的关键机制:

### 3.1 ESVR 体素化器是"直接相加",不是"透明度合成"

ESVR 的 CUDA 体素化核心(`submodules/gaussian-rasterization-voxelization`)对每个体素,把所有覆盖到它的椭球的 `opacity * sigmoid(shape)` 贡献**直接累加**(`forward.cu` 注释原文:`// Simply add all alphas; C[ch] += alpha;`),而不是像三篇 donor 论文自己的渲染器那样做基于深度顺序的**透明度合成**(alpha compositing)。这个差异是本项目里好几个 bug/现象的根源,尤其是"增密(densification)为什么在某些方法上会让效果变差"这件事——透明度合成下,新增的近似重复图元会被后面的图元遮挡削弱;纯相加下,新增图元的贡献是直接叠加的,容易让局部值失控变大。

### 3.2 共享的 CUDA 位置梯度 bug(已修复)

`cuda_voxelizer/backward.cu` 里,位置梯度从体素下标空间转换回世界坐标空间时,系数写反了(`ddelx_dx` 等被设成了 `dVoxel`,正确应该是 `1/dVoxel`)。这是从原版 3DGS 相机光栅化器的代码里直接照搬过来、没有针对这个场景改对的历史遗留问题,**在这个仓库最原始未修改的官方版本(`hvcl/ESVR`)里就已经存在**,不是本项目引入的。

- 后果:每一次位置梯度都被压缩了 `dVoxel²` 倍,这个仓库统一用 128³ 网格,压缩倍数约 4096 倍。
- 已经在三个方法分支(`codex/deformable-esvr`、`codex/4dgs-esvr`、`codex/scaffold4d-esvr`)里都修复(同一个 patch,cherry-pick 到三条独立历史上,内容一致、commit hash 不同,这是正常现象)。**没有**应用到原始 `ESVR` 文件夹或 `main` 分支。
- 修复后位置梯度变成正确大小,直接沿用旧的 `position_lr` 会导致训练发散/显存溢出——必须把 `position_lr` 按 ÷4096 反向补偿,才能在"梯度修正"这一个变量之外,不引入"有效步长突变"这第二个变量。`densify_grad_threshold` **不需要**同样反向补偿(这一点最初凭直觉判断错了方向,已经用实验纠正)。
- ~~**修复本身的真实代价已经被严格量化**:单帧静态重建 41.77dB → 39.94dB(−1.83dB);90 帧完整原生流程 41.22dB → 39.38dB(−1.84dB)——两次独立测量几乎完全一致,互相印证,这不是偶然。~~ **2026-09-22 更正**:这两次"修复核对照"实际通过 `source .venv/bin/activate` 运行在**未修复核**上(该 activate 脚本是从 `ESVR/` 复制来的,指向 `ESVR/.venv`),量到的是"位置学习率 ÷4096"的代价。在真正的修复核上,原生学习率不变、只把增密阈值 ×4096,单帧得到 41.72dB(与 41.77 一致):修复本身没有代价。位置学习率不需要补偿(Adam 对梯度尺度不敏感),需要补偿的是增密阈值。证据与容量扫描见 `output/experiments/static_ceiling/RESULTS.md`。

### 3.3 共享的"学习率分组混淆" bug 模式(三个方法都独立发现并修复过)

三篇 donor 论文自己的实现里,canonical/基础参数(位置、缩放、旋转、透明度)从来都是 4~7 个独立的优化器参数组,量级能差到上千倍。本项目最初把这些参数错误地合并成了一个共享学习率,三个方法都各自犯过这个错、也都各自修复过。修复方式统一是:拆成独立的具名优化器参数组 + 一个 `expon_lr`(对数线性衰减)辅助函数,数值上参考各自最合适的原生来源(细节见第 4 节每个方法各自的说明)。

**修复效果因方法而异,而且方向相反**:让 Deformable-MLP 变好(+2.9dB,运动由不受这个 bug 影响的独立形变网络承载),让 ESVR4D 变差(−3.09dB,已用步数对齐的干净对照验证过,运动直接依赖 xyz 本身移动,原生更保守的位置学习率束缚了运动表达)。

### 3.4 "时间"是怎么被处理的

三种方法(以及验证过的三篇 donor 论文自己的官方实现)都遵循同一个架构模式:**"时间"这个维度,在 Python 层面被坍缩成某一个具体时刻的一组普通静态椭球参数(位置/尺度/旋转/透明度),然后才交给 CUDA 体素化器**——CUDA 核心本身从头到尾都不需要、也没有任何"时间"的概念。这不是本项目发明的简化,是三篇论文自己代码的设计方式(逐一读过官方源码确认过)。唯一的例外和细微差别:4DGS 官方代码同时支持"在 CUDA 里做这个时间条件化"这条更快的路径,并且**论文正式实验用的就是这条路径**;本项目的 ESVR4D 实现走的是数学等价、但更慢的 Python 路径——这是一个性能差异,不是正确性缺陷。

## 4. 三种方法各自的实现状态

### 4.1 Deformable-MLP(分支 `codex/deformable-esvr`)

- **核心文件**:`train_dynamic.py`、`dynamic_esvr/model.py`(`DynamicESVR` 类 + 形变网络)
- **表征**:canonical 椭球(位置/对数尺度/旋转/透明度 logit)+ 8 层、256 宽的形变 MLP,输入是位置和时间各自的 Fourier 位置编码,输出对 canonical 姿态的位移/旋转/尺度偏移。
- **增密**:从一开始就没有实现,是刻意的设计决定——donor 论文自己的增密判据基于相机屏幕空间 2D 梯度,这个体素场景里根本不存在对应的量,所以全程固定图元数量,没有 coarse→fine 的过程。
- **已修复**:共享的 CUDA 位置梯度 bug;自己的学习率分组混淆 bug。
- **当前最好结果**:平均 **28.895dB**,`output/dynamic/vorts90_native_canonical_lr/`,40,000 步,3 万图元固定、随机初始化,4 组原生学习率(canonical 位置/尺度/旋转分别用 ESVR 自己静态重建验证过的值,形变网络用 donor 自己的值)。
- **未解决/待商榷**:canonical 参数的学习率来源用的是 **ESVR 自己**静态重建的原生值,而不是 Deformable 3DGS 论文自己 `arguments/__init__.py` 里的原生默认值——这是一个经过讨论但没有最终定论的设计选择(理由:canonical 参数在数学上等价于 ESVR 自己的静态表征,运动完全由独立的形变网络承载),和 ESVR4D、Scaffold4D 统一使用 donor 论文自己原生值的做法不一致,如果要严格统一"三个方法学习率来源的标准",这里需要重新考虑。

### 4.2 ESVR4D(分支 `codex/4dgs-esvr`)

- **核心文件**:`train_esvr4d.py`、`esvr4d/model.py`
- **表征**:原生 4D 时空椭球(位置、时间、4D 对数尺度、双四元数 SO(4) 旋转、标量透明度 logit),运动通过对 4D 协方差做时间条件化(Schur 补)自然产生,没有额外网络。
- **增密**:代码实现了,但**在真实数据的正式实验里被主动关闭**——不是训练崩溃,是经过对照实验证实开增密后重建质量反而更差(3 帧平均 16.5dB vs 关闭时 18.4dB,同等步数下),根源部分诊断为 3.1 节提到的"加法渲染"机制(分裂/克隆出的近似重复图元让局部值翻倍),做过一次"分裂时透明度减半"的补偿但没能完全解决,还有一个未查明的次要因素。
- **已修复**:共享的 CUDA 位置梯度 bug;自己的学习率分组混淆 bug(验证后发现让结果变差,见 3.3 节)。
- **当前代表性结果**:两个数字都有意义,不能只取一个——`output/esvr4d/vorts90_fixed_points/`(合并学习率组的历史版本)28.772dB;`output/esvr4d/vorts90_native_lr_40k/`(结构正确的 5 组原生学习率,步数对齐的干净对照)25.68dB。项目立场是把后者(25.68dB)当作"公平"的代表数字,即使它更低——因为它反映的是一次正确性修复,不是调参退步。
- **未解决**:增密质量回归的第二个未查明因素;没有实现 4DGS 论文官方使用的 CUDA 加速条件化路径(性能优化,非正确性问题)。

### 4.3 Scaffold4D(分支 `codex/scaffold4d-esvr`)

- **核心文件**:`train_scaffold4d.py`、`scaffold4d/model.py`
- **表征**:稀疏"锚点" + 共享 MLP 解码器(透明度/形状/光流三个头),每个锚点生成若干个子椭球,恒定速度运动模型。
- **真实崩溃 bug,已修复**:(1)透明度激活函数用 `Tanh`+硬掩码,在所有锚点特征零初始化的前提下,导致全部子椭球在训练早期集体死亡且无法恢复——换成 `sigmoid` 解决;(2)最终尺度乘积没有下限,真实数据训练里会在不确定的某一步(每个随机种子都不一样)因为尺度塌缩到 `~1e-9~1e-10` 导致 CUDA 里协方差矩阵奇异,loss 变成 NaN——加了 `clamp_min` 下限解决;(3)另外还修了一个 `retain_grad()` 缺失的 bug,这个 bug 会让增密统计量永远收不到梯度,是静默失效不是崩溃。
- **增密**:是三个方法里**唯一**修复问题后能完整开着增密跑完全程原生训练步数的(120,000 步,锚点数从初始 6,000 真实涨到封顶的 40,000,全程没有崩溃)。
- **当前最好结果**:平均 **24.348dB**,`output/scaffold4d/vorts90_native_recipe/`,论文原生 7 组学习率,120,000 步。
- **未解决(codex 审查提出、尚未处理)**:锚点是随机初始化后再冻结(原生学习率 `anchor_lr=0`),这不等价于上游语义——上游锚点来自真实点云体素化,本身就落在有效结构附近,冻结才有意义;当前随机初始化+冻结,理论上没法把锚点主体移动到真实数据结构上。此外,增密时用 `anchor_feat *= 0.5` 近似补偿子透明度减半,这是启发式做法,因为透明度来自带偏置的非线性 MLP,`MLP(feature*0.5) ≠ MLP(feature)*0.5` 在数学上不成立。

## 6. 已建立的方法论与工作习惯

这部分记录的是"怎么做事的规矩",不是某个具体结果,但对保持交接后工作质量的一致性很重要:

- **先验证,不轻信**:任何一个汇报出去的关键数字,都会从最原始的 `metrics.json`/checkpoint 文件里独立重新计算一遍,不直接引用训练过程里打印出来的数字。
- **Checkpoint 重载一致性校验**:每一次正式的真实数据训练完成后,都会用 `--eval-only --resume checkpoint.pt` 到一个全新目录重新跑一遍推理,逐字节比较导出的 `.npy`(要求 `max abs diff == 0.0`),确认存下来的模型和训练时的状态完全一致。
- **多随机种子压力测试**:遇到不稳定的新代码(尤其是 Scaffold4D 那两个崩溃 bug),会先跑 3~8 组不同随机种子的短时间压力测试,确认稳定后才投入昂贵的真实完整训练。
- **对照官方源码,而不是凭记忆**:每次要下"和官方实现一致/不一致"这种结论之前,都会重新 clone 一份对应版本的官方仓库(固定到具体 commit),逐字节 diff 或者逐函数对照读代码,不凭印象下结论。
- **主动识别并标注"混淆变量"**:这个项目里反复出现过"两个实验看起来能直接比,其实差了不止一个变量"的情况(PLY 热启动 vs 随机初始化;学习率修复的同时意外改了步数;两个"90帧独立"基线其实用的是完全不同的训练脚本),每次发现后都会在报告里明确标注哪些对比是"单变量、可信"的,哪些不是。
- **git 提交习惯**:`output/` 目录下只提交 `RESULTS.md`,大文件一律 `.gitignore`;失败/被取代的实验保留记录、明确标注"已废弃"而不是直接删除;跨方法共享的内容三个分支各放一份,方法专属内容只放在对应那一个分支。

## 7. 尚未完成/待解决的问题清单(按优先级)

**最高优先级**:
- **从未做过留出时间点的泛化测试**。目前所有 90 帧实验用的都是"90/90 帧全部参与训练"的清单,从未验证过任何一种方法是否学到了真正可以插值/外推的连续运动场,还是仅仅利用参数容量记住了 90 个已知的训练约束。这是目前最大的、尚未触及的验证空白,如果要往"这个方法真的建模了运动"这个方向做结论,必须先补上这个测试。

**较高优先级**:
- **三个方法分支仍未推送到任何远程仓库**——用户已明确决定暂不推送,不是遗漏,但一旦决定推送,第 2 节记录的分支重名冲突风险(`ESVR` 和 `ESVR-4dgs` 共享同一个远程)必须先处理。
- ESVR4D 增密质量回归还有一个未查明的次要因素(见 4.2)。
- Scaffold4D 随机初始化+冻结锚点,不等价于原生的结构感知初始化语义(见 4.3)。
- Deformable-MLP canonical 学习率来源(ESVR 自己 vs donor 自己)的设计不一致,没有最终定论(见 4.1)。

**中等优先级(codex 代码审查提出,尚未处理)**:
- 三个分支的 Adam 优化器都没有使用三篇 donor 论文原生统一采用的 `eps=1e-15`(目前用的是 PyTorch 默认 `1e-8`),七个数量级的差异在小尺度协方差场景下可能不该忽略。
- Scaffold4D 增密时 `anchor_feat *= 0.5` 补偿子透明度减半的做法,数学上不严谨(见 4.3)。
- 若干次要项:命令行参数校验不完整(部分学习率参数没检查非正/非负)、旧版本 checkpoint 恢复训练时会抛出不友好的 `AttributeError` 而不是清晰的报错信息。

**低优先级(已确认不紧急,暂缓处理)**:
- 三个训练脚本(`train_dynamic.py`/`train_esvr4d.py`/`train_scaffold4d.py`)之间大约 70% 的代码是重复的(manifest 校验、checkpoint 保存、block 采样、评估导出等),可以抽取成公共模块,但决定暂缓重构,避免和正确性修复混在同一批改动里,增加复查难度。
- `utils/loss_utils.py` 里有一个和当前三个方法都无关的拼写 bug(`"centeral"` 应为 `"central"`,导致对应分支永远走不到),已确认是死代码,不影响任何已汇报的结果,优先级最低。

## 8. 已知限制 / 容易踩的坑

- **`train_chunk.py` 的路径怪癖**:这个脚本自己会在 `--output_dir` 前面再加一层 `output/` 前缀,导致真实产物路径变成 `output/output/.../xxx_chunk_0/`,不是 bug,是这个脚本一直以来的行为,建立目录时容易被误以为是双重创建的错误目录。
- **两个"90帧独立、互不共享参数"的基线不能直接互相比较**:`output/esvr_original_per_frame/`(原始 `ESVR` 文件夹,`train_chunk.py` 原生配方,未修 CUDA)和 `output/esvr_per_frame_baseline/`(副本,`train_dynamic.py --allow-single-frame` 简化配方,已修 CUDA)同时差了训练脚本、图元策略、迭代次数、学习率四个变量,不能把两者的差值归因于任何单一原因(这也是为什么后来专门补了 `output/experiments/vorts90_cuda_fixed_lr_only/` 这一组真正的单变量对照)。
- **90 帧逐帧数据集配置**(`dataset_configs.py` 里的 `vorts_frame_0001`..`vorts_frame_0090` 条目)一开始只加在了原始 `ESVR` 文件夹里,后来因为要做单变量 CUDA 对照,又补加回了副本 `ESVR-4dgs` 的三个方法分支——目前三个方法分支和原始文件夹里都有这些条目了,但如果继续在其他地方(比如 `main` 分支)工作,记得检查这些条目是否存在。
- **`vorts0001` 这份数据在磁盘上有两个路径**:`data/xueliao_data/vorts0001.raw` 和 `data/xueliao_timevaryingdata/vorts_timevarying/vorts0001.raw`,已经用 SHA256 确认是完全相同的文件,只是两个入口,容易让人误以为是两份不同的数据。

## 10. 术语表

| 术语 | 含义 |
|---|---|
| ESVR | 本项目基于的原始静态 3D 标量体重建方法,用椭球图元 + CUDA 体素化渲染 |
| PSNR | 峰值信噪比,重建质量的主要评价指标,本项目里统一用归一化 [0,1] 值域下的 3D 体素 PSNR |
| DVR | Direct Volume Rendering,直接体渲染,把整个 3D 体数据沿视线方向合成投影成一张 2D 图像,用于可视化 |
| coarse → fine | 先用较少、较大的图元粗略拟合,再通过增密逐步精细化的两阶段训练范式 |
| 增密(densification) | 训练过程中动态增加/裁剪图元数量的机制,和"从头到尾固定图元数量"相对 |
| checkpoint | 训练过程中保存的模型快照,含参数和优化器状态,用于断点续训或推理 |
| RESULTS.md | 本项目约定的实验报告文件,每个实验目录下都应该有一份,是唯一会被 git 追踪的实验产物 |
| 单变量对照 | 只改变一个因素、其余全部保持一致的对照实验,本项目反复强调的严谨性要求 |
